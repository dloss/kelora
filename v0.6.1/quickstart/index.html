    Quickstart¶

    Get started with Kelora in 5 minutes. This guide will walk you through parsing, filtering, and transforming logs using real example files.

    Prerequisites¶

    • Kelora installed and on your PATH
    • Clone the repository to access example files: git clone https://github.com/dloss/kelora

    Step 1: Parse JSON Logs¶

    Let's start with a simple JSON log file. Parse it and see all events:

    kelora -f json examples/simple_json.jsonl --take 3

    timestamp='2024-01-15T10:00:00Z' level='INFO' message='Application started' service='api'
  version='1.2.3'
timestamp='2024-01-15T10:00:05Z' level='DEBUG' message='Loading configuration' service='api'
  config_file='/etc/app/config.yml'
timestamp='2024-01-15T10:00:10Z' level='INFO' message='Connection pool initialized'
  service='database' max_connections=50

    The -f json flag tells Kelora to parse each line as JSON. By default, Kelora outputs events in key=value format. The --take 3 flag limits output to the first 3 events.

    Step 2: Filter by Log Level¶

    Show only error-level events:

    kelora -f json examples/simple_json.jsonl --levels error

    timestamp='2024-01-15T10:01:30Z' level='ERROR' message='Query timeout' service='database'
  query='SELECT * FROM users' duration_ms=5000
timestamp='2024-01-15T10:03:30Z' level='ERROR' message='Account locked' service='auth'
  username='admin' attempts=5
timestamp='2024-01-15T10:16:00Z' level='ERROR' message='Service unavailable' service='api'
  reason='disk space'

    The --levels flag filters events by their log level field. You can specify multiple levels: --levels warn,error.

    Step 3: Select Specific Fields¶

    Extract just the fields you care about:

    kelora -f json examples/simple_json.jsonl \
  --keys timestamp,service,message \
  --take 3

    timestamp='2024-01-15T10:00:00Z' service='api' message='Application started'
timestamp='2024-01-15T10:00:05Z' service='api' message='Loading configuration'
timestamp='2024-01-15T10:00:10Z' service='database' message='Connection pool initialized'

    The --keys flag limits output to specified top-level fields.

    Step 4: Filter with Custom Logic¶

    Use Rhai scripts to filter events with custom conditions:

    kelora -f json examples/simple_json.jsonl \
  --filter 'e.service == "database"' \
  --keys timestamp,service,message

    timestamp='2024-01-15T10:00:10Z' service='database' message='Connection pool initialized'
timestamp='2024-01-15T10:01:30Z' service='database' message='Query timeout'

    The --filter flag evaluates a Rhai expression. Events where the expression returns true are kept.

    Step 5: Transform Event Data¶

    Add computed fields using --exec:

    kelora -f json examples/simple_json.jsonl \
  --filter 'e.service == "database"' \
  --exec 'e.duration_s = e.get_path("duration_ms", 0) / 1000' \
  --keys timestamp,message,duration_s

    timestamp='2024-01-15T10:00:10Z' message='Connection pool initialized' duration_s=0
timestamp='2024-01-15T10:01:30Z' message='Query timeout' duration_s=5

    The --exec flag runs Rhai code to modify events. Here we convert milliseconds to seconds.

    Step 7: Parse Other Formats¶

    Kelora supports many formats out of the box:

    Logfmt¶

    kelora -f logfmt examples/simple_logfmt.log --levels error

    timestamp='2024-01-15T10:02:00Z' level='error' msg='Query timeout' service='db'
  query='SELECT * FROM large_table' duration=5000
timestamp='2024-01-15T10:04:30Z' level='error' msg='Rate limit exceeded' service='rate_limiter'
  ip='10.0.0.5' current=101 limit=100
timestamp='2024-01-15T10:13:00Z' level='error' msg='API call failed' service='external_api'
  endpoint='https://api.partner.com' status=503 retry=1

    Apache/Nginx Access Logs¶

    kelora -f combined examples/web_access_large.log.gz \
  --filter 'e.status >= 400' \
  --keys ip,status,request \
  --take 3

    ip='120.180.198.77' status=403 request='GET /reintermediate/e-commerce/cross-platform HTTP/1.0'
ip='83.14.202.89' status=500 request='PUT /infrastructures/customized/portals/enhance HTTP/1.1'
ip='169.247.105.115' status=406 request='PATCH /e-business HTTP/2.0'

    CSV¶

    kelora -f csv examples/simple_csv.csv \
  --keys method,path,status \
  --take 5

    method='GET' path='/' status='200'
method='GET' path='/api/users' status='200'
method='POST' path='/api/login' status='200'
method='GET' path='/api/users/123' status='200'
method='PUT' path='/api/users/123' status='200'

    Common Patterns¶

    Stream Processing¶

    Process logs as they're written:

    > tail -f /var/log/app.log | kelora -j --levels error

    > Get-Content -Wait app.log | kelora -j --levels error

    Gzipped Files¶

    Kelora automatically decompresses .gz files:

    > kelora -f json app.log.gz --levels error

    Multiple Files¶

    Process multiple files in sequence:

    > kelora -f json logs/*.jsonl --levels error

    Output to JSON¶

    Change the output format:

    > kelora -f logfmt examples/simple_logfmt.log -F json

    Quick Recipes¶

    Need a refresher later? These bite-sized snippets mirror the built-in fixtures so you can rehearse common tasks quickly. Run them from the repository root so the examples/ paths resolve.

    Narrow to a specific service¶

    kelora -f json examples/simple_json.jsonl \
  --filter 'e.service == "database"' \
  --exec 'e.duration_s = e.get_path("duration_ms", 0) / 1000' \
  --keys timestamp,message,duration_s

    timestamp='2024-01-15T10:00:10Z' message='Connection pool initialized' duration_s=0
timestamp='2024-01-15T10:01:30Z' message='Query timeout' duration_s=5

    Slice logs by prefix before parsing¶

    cat examples/prefix_docker.log | \
  kelora --extract-prefix container --prefix-sep ' | ' \
    --filter 'e.container == "web_1"'

    line='2024-01-15 10:00:00 [INFO] Starting web server on port 8080' container='web_1'
line='2024-01-15 10:00:05 [INFO] Listening for connections' container='web_1'
line='2024-01-15 10:00:30 [INFO] Connected to database' container='web_1'
line='2024-01-15 10:00:35 [DEBUG] Cache connection established' container='web_1'
line='2024-01-15 10:01:00 [INFO] Received request GET /api/health' container='web_1'
line='2024-01-15 10:01:05 [INFO] Health check passed' container='web_1'
line='2024-01-15 10:01:30 [ERROR] Request timeout after 5s' container='web_1'

    Quick Reference¶

    # Common flags
kelora --help              # Complete CLI reference
kelora --help-functions    # All built-in Rhai functions
kelora --help-examples     # Common usage patterns
kelora --help-rhai         # Rhai scripting guide

# Format shortcuts
-j                        # Shorthand for -f json
-f auto                   # Auto-detect format
-F json                   # Output as JSON

# Filtering
--levels error            # Filter by log level
--filter 'expression'     # Custom Rhai filter
--since "1 hour ago"      # Time-based filtering
--until "2024-01-01"      # Upper time bound

# Transformation
--exec 'expression'       # Transform events
--keys field1,field2      # Select fields
--stats                   # Show processing statistics
--metrics                 # Show tracked metrics

# Performance
--parallel                # Use multiple cores
--take 100                # Limit to first 100 events
