    Quickstart¶

    Get started with Kelora in 5 minutes. This guide will walk you through parsing, filtering, and transforming logs using real example files.

    Prerequisites¶

    • Kelora installed and on your PATH
    • Clone the repository to access example files: git clone https://github.com/dloss/kelora

    Step 1: Parse JSON Logs¶

    Let's start with a simple JSON log file. Parse it and see all events:

    kelora -j examples/simple_json.jsonl -n 3

    timestamp='2024-01-15T10:00:00Z' level='INFO' message='Application started' service='api'
  version='1.2.3'
timestamp='2024-01-15T10:00:05Z' level='DEBUG' message='Loading configuration' service='api'
  config_file='/etc/app/config.yml'
timestamp='2024-01-15T10:00:10Z' level='INFO' message='Connection pool initialized'
  service='database' max_connections=50

    The -j flag (short for -f json) tells Kelora to parse each line as JSON. By default, Kelora outputs events in key=value format. The -n 3 flag limits output to the first 3 events.

    Step 2: Filter by Log Level¶

    Show only error-level events:

    kelora -j examples/simple_json.jsonl -l error

    timestamp='2024-01-15T10:01:30Z' level='ERROR' message='Query timeout' service='database'
  query='SELECT * FROM users' duration_ms=5000
timestamp='2024-01-15T10:03:30Z' level='ERROR' message='Account locked' service='auth'
  username='admin' attempts=5
timestamp='2024-01-15T10:16:00Z' level='ERROR' message='Service unavailable' service='api'
  reason='disk space'

    The -l (or --levels) flag filters events by their log level field. You can specify multiple levels: -l warn,error.

    Step 3: Select Specific Fields¶

    Extract just the fields you care about:

    kelora -j examples/simple_json.jsonl \
  -k timestamp,service,message \
  -n 3

    timestamp='2024-01-15T10:00:00Z' service='api' message='Application started'
timestamp='2024-01-15T10:00:05Z' service='api' message='Loading configuration'
timestamp='2024-01-15T10:00:10Z' service='database' message='Connection pool initialized'

    The -k (or --keys) flag limits output to specified top-level fields. Use -b (or --brief) to show only values:

    kelora -j examples/simple_json.jsonl \
  -k timestamp,service,message \
  -b \
  -n 3

    2024-01-15T10:00:00Z api Application started
2024-01-15T10:00:05Z api Loading configuration
2024-01-15T10:00:10Z database Connection pool initialized

    Step 4: Filter with Custom Logic¶

    Use Rhai scripts to filter events with custom conditions:

    kelora -j examples/simple_json.jsonl \
  --filter 'e.service == "database"' \
  -k timestamp,service,message

    timestamp='2024-01-15T10:00:10Z' service='database' message='Connection pool initialized'
timestamp='2024-01-15T10:01:30Z' service='database' message='Query timeout'

    The --filter flag evaluates a Rhai expression. Events where the expression returns true are kept.

    Step 5: Transform Event Data¶

    Add computed fields using -e (or --exec):

    kelora -j examples/simple_json.jsonl \
  --filter 'e.service == "database"' \
  -e 'e.duration_s = e.get_path("duration_ms", 0) / 1000' \
  -k timestamp,message,duration_s

    timestamp='2024-01-15T10:00:10Z' message='Connection pool initialized' duration_s=0
timestamp='2024-01-15T10:01:30Z' message='Query timeout' duration_s=5

    The -e flag runs Rhai code to modify events. Here we convert milliseconds to seconds.

    Step 6: Track Metrics¶

    Count events by service and show metrics, suppressing event output:

    kelora -j examples/simple_json.jsonl \
  -e 'track_count(e.service)' \
  -F none \
  -m

    kelora: Tracked metrics:
admin        = 2
api          = 7
auth         = 2
cache        = 1
database     = 2
disk         = 1
health       = 1
monitoring   = 1
scheduler    = 3

    The track_count() function increments a counter for each unique value. The -F none flag suppresses event output, and -m (or --metrics) displays the accumulated counts.

    Step 7: Convert Between Formats¶

    Kelora can convert logs from any input format to any output format:

    Syslog to JSON¶

    kelora -f syslog examples/simple_syslog.log -J -n 3

    {"timestamp":"Oct 04 10:27:22","severity":0,"msg":"You can't reboot the capacitor without compressing the virtual CSS alarm!","pri":96,"facility":12,"host":"bernier5641","prog":"dolore","pid":7276}
{"timestamp":"Oct 04 10:27:22","severity":3,"msg":"If we synthesize the pixel, we can get to the RSS array through the bluetooth SDD sensor!","pri":131,"facility":16,"host":"gusikowski6748","prog":"eaque","pid":4669}
{"timestamp":"Oct 04 10:27:22","severity":4,"msg":"Use the 1080p SDD program, then you can transmit the online program!","pri":132,"facility":16,"host":"gerlach2033","prog":"non","pid":4398}

    Logfmt to JSON¶

    kelora -f logfmt examples/simple_logfmt.log -J -n 3

    {"timestamp":"2024-01-15T10:00:00Z","level":"info","msg":"Server started","service":"web","port":8080}
{"timestamp":"2024-01-15T10:00:05Z","level":"debug","msg":"Loading middleware","service":"web","count":5}
{"timestamp":"2024-01-15T10:00:10Z","level":"info","msg":"Connection pool ready","service":"db","size":20}

    Apache/Nginx Logs to CSV¶

    kelora -f combined examples/web_access_large.log.gz \
  -F csv \
  -k ip,status,request \
  -n 3

    ip,status,request
120.180.198.77,403,GET /reintermediate/e-commerce/cross-platform HTTP/1.0
83.14.202.89,500,PUT /infrastructures/customized/portals/enhance HTTP/1.1
233.208.89.13,301,PUT /enterprise/iterate/integrate/exploit HTTP/2.0

    The -f flag specifies input format, -F (or -J for JSON) specifies output format. Kelora normalizes all formats to a common event structure.

    Common Patterns¶

    Stream Processing¶

    Process logs as they're written:

    > tail -f /var/log/app.log | kelora -j -l error

    > Get-Content -Wait app.log | kelora -j -l error

    Gzipped Files¶

    Kelora automatically decompresses .gz files:

    > kelora -j app.log.gz -l error

    Multiple Files¶

    Process multiple files in sequence:

    > kelora -j logs/*.jsonl -l error

    Quick Recipes¶

    Need a refresher later? These bite-sized snippets mirror the built-in fixtures so you can rehearse common tasks quickly. Run them from the repository root so the examples/ paths resolve.

    Narrow to a specific service¶

    kelora -j examples/simple_json.jsonl \
  --filter 'e.service == "database"' \
  -e 'e.duration_s = e.get_path("duration_ms", 0) / 1000' \
  -k timestamp,message,duration_s

    timestamp='2024-01-15T10:00:10Z' message='Connection pool initialized' duration_s=0
timestamp='2024-01-15T10:01:30Z' message='Query timeout' duration_s=5

    Slice logs by prefix before parsing¶

    cat examples/prefix_docker.log | \
  kelora --extract-prefix container --prefix-sep ' | ' \
    --filter 'e.container == "web_1"'

    line='2024-01-15 10:00:00 [INFO] Starting web server on port 8080' container='web_1'
line='2024-01-15 10:00:05 [INFO] Listening for connections' container='web_1'
line='2024-01-15 10:00:30 [INFO] Connected to database' container='web_1'
line='2024-01-15 10:00:35 [DEBUG] Cache connection established' container='web_1'
line='2024-01-15 10:01:00 [INFO] Received request GET /api/health' container='web_1'
line='2024-01-15 10:01:05 [INFO] Health check passed' container='web_1'
line='2024-01-15 10:01:30 [ERROR] Request timeout after 5s' container='web_1'

    Quick Reference¶

    # Common flags
kelora --help              # Complete CLI reference
kelora --help-functions    # All built-in Rhai functions
kelora --help-examples     # Common usage patterns
kelora --help-rhai         # Rhai scripting guide

# Format shortcuts
-j                        # Shorthand for -f json
-f auto                   # Auto-detect format
-F json                   # Output as JSON

# Filtering
-l error                  # Filter by log level (--levels)
--filter 'expression'     # Custom Rhai filter
--since "1 hour ago"      # Time-based filtering
--until "2024-01-01"      # Upper time bound

# Transformation
-e 'expression'           # Transform events (--exec)
-k field1,field2          # Select fields (--keys)
-s                        # Show processing statistics (--stats)
-m                        # Show tracked metrics (--metrics)

# Output
-b                        # Brief mode - values only (--brief)
-n 100                    # Limit to first 100 events (--take)

# Performance
--parallel                # Use multiple cores
