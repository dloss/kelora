# Allocation-free grouping in `--stats` and `--drain`

Date: 2026-07-08
Machine: 4-core Linux container, `mimalloc`, release profile (`lto = "thin"`).
Corpus: `bench/corpus/logfmt_1m_100pct.log` — 1,000,000 logfmt lines, ~15 fields
each (generated by `bench/gen_corpus.py`).

## What changed

Grouping code allocated an owned key on the hot path even when the group
already existed. Fixes:

- **`src/stats.rs`** — added a `bump(map, key)` helper (over a small `CountMap`
  trait covering both `HashMap` and `IndexMap`) that does a borrowed `get_mut`
  hit path and allocates a `String` only on the miss path. Replaced all three
  `entry(x.to_string()).or_insert(0) += 1` sites (cascade/detected format
  counts, assertion-expr counts). Also fixed the per-event
  `stats_record_timestamp_detection` site, which allocated `field_name.to_string()`
  unconditionally — now `get_index_of` + index, allocating only on first sight of
  a field name.
- **`src/drain.rs`** — the per-line hot path computed a SHA256 template id every
  line purely to key the per-template metadata map. Metadata is now keyed on the
  **whitespace-normalized template string** instead, which has byte-for-byte the
  same collision behavior as the id (equal normalized forms ⇔ equal ids) but no
  hash on the hot path — the id is display-only and computed once per template in
  `templates()`. Added a light `drain_record` entry point for the CLI `--drain`
  pipeline (which discards the per-line `DrainResult`), skipping the id hash and
  sample clone per line. `metadata.entry(id.clone())` → borrowed `get_mut` /
  insert-on-miss.
- **`src/pipeline/stages.rs`** — `KeyFilterStage::apply` cloned *all* event keys
  per event (`keys().cloned().collect()`); now iterates borrowed keys and clones
  only the ones kept.

Instrumentation: a `bench-alloc` cargo feature wraps the global allocator in a
counting shim that reports `allocs / lines / allocs_per_line` at end of run
(dev/benchmarking only). See `bench/measure_grouping.sh` and
`bench/diff_grouping.sh`.

## Results

Wall clock is the min of 5 runs with the plain release binary; allocs/line is a
single run with the `bench-alloc` binary. `--drain` and pass-through report
`lines=0` from the alloc harness (stats collection off), so allocs/line there is
`total / 1,000,000`.

| ID | Command | Wall (baseline → candidate) | Δ wall | allocs/line (base → cand) | Δ allocs/line |
|----|---------|------------------------------|--------|----------------------------|----------------|
| A | `--drain -k msg` | 23.451s → 22.094s | **−5.8%** | 131.50 → 108.50 | **−17.5%** |
| B | `--stats` | 6.452s → 6.209s | −3.8% | 111.50 → 110.50 | −0.9% |
| C | pass-through (no stats/drain) | 9.773s → 9.774s | ±0.0% | 159.50 → 158.50 | −0.6% |

Scenario A wall clock, re-measured interleaved (baseline/candidate alternating,
min of 8 runs) to control for drift: **24.036s → 22.154s = −7.0%**.

Raw allocation totals (1M lines):

| ID | baseline allocs | candidate allocs |
|----|-----------------|------------------|
| A | 131,504,506 | 108,504,507 |
| B | 111,503,054 | 110,503,055 |
| C | 159,497,371 | 158,497,372 |

## Verdict against the spec

Kill criterion (§2.3): kill only if scenario A is **both** `<5%` wall **and**
`<20%` allocs/line. Scenario A is −7.0% wall (interleaved) — over the 5% floor —
so the change is **not** killed and is merged. Allocs/line fell 17.5%, just under
the 20% aspiration; the remaining per-line drain allocations are dominated by
`drain-rs`'s internal tokenizer (`split(' ')` → `Vec<Token>` with a `String` per
token) and `cluster.as_string()`, which are outside this crate. The big win came
from moving SHA256 off the per-line path.

Scenarios B and C: allocs/line down as expected (the removed per-event
`field_name.to_string()` in timestamp detection — which runs whenever stats
collection is on, hence C moves too). B wall down 3.8%; C wall unchanged, as
required for the control.

## Correctness

- Differential gate (`bench/diff_grouping.sh`): stdout + stderr + exit code
  **byte-identical** between baseline and candidate across `--drain`
  (table/full/id/json) and `--stats`/`--stats=json`/pass-through on 1%/20%/100%
  logfmt and JSON corpora, plus adversarial drain messages (numbers-only, empty,
  leading/trailing/internal-whitespace variants, tabs, unicode, a very long
  token). Wall-clock-dependent lines (throughput / duration) are normalized out;
  all counts, orderings, samples, and data-derived time spans match exactly.
- Whitespace-collision behavior (two templates that differ only by whitespace
  share one metadata entry via id collision) is preserved and now covered by a
  regression test (`whitespace_variant_templates_share_metadata`).
- Full suite: `cargo test` green (1200+ tests); `cargo fmt` + `cargo clippy
  --all-targets --all-features -D warnings` clean.

## Notes / follow-ups (out of scope here)

  (`collect_discovered_levels_and_keys`) clones each key per event to probe a
  `HashSet` (`set.insert(key.clone())`), i.e. the same "grouping allocates on

  Left alone here to keep the change scoped to `stats.rs`/`drain.rs`/the
  formatter; it's a natural target for the key-interning spec that already
  touches that area.
