# Level pre-filter — before/after results

Raw-line level pre-filter for `--levels`: before parsing, scan the assembled raw
line for the accepted level tokens; drop the line without parsing when none
appear. Full design and safety gate in the spec and the implementation commit.

## Environment

- CPU: Intel(R) Xeon(R) @ 2.80GHz, 4 cores
- OS: Ubuntu 24.04.4 LTS, Linux 6.18.5 x86_64
- rustc 1.86.0, release profile (`cargo build --release`)
- hyperfine 1.18.0 (`--warmup 3 --min-runs 10`)
- Corpora: 1,000,000 lines each, generated by `bench/gen_corpus.py` (seeded)

## Binaries (benchmarked back-to-back in one hyperfine invocation per scenario)

- Baseline:  `b3072cfcc591da5c1a833d12945f2ce020d659e1` (frozen at `bench/bin/kelora-baseline`)
- Candidate: `7aaf2f7f001ff749613ea0bdb72b4151596b0f70` (this change)

## Acceptance criteria

1. **Differential tests: zero diffs.** `bench/diff_check.sh` runs 26 cases
   (scenarios A–F on both formats, plus `--exclude-levels`, `--filter` before and
   after the level filter, `--exec`, `--keys`, `--drain`, `-f syslog`, multiline
   with the token on a continuation line, `--stats`, and malformed input on the
   keep path). stdout, stderr, and exit code are byte-identical for every case.
2. **Scenario A ≥ 25% wall-clock improvement.** Achieved **87.8%** (logfmt) and
   **84.3%** (json) — far above the bar.
3. **Scenarios C, D, E regression ≤ 2%.** C (clean): −0.2% / +0.2%. D: −1.9% /
   +1.0%. E: −4.5% / −2.1% (both improvements). All within tolerance.

## Interpretation

The pre-filter delivers exactly where the spec predicted: when matches are
sparse (scenario A, 1% of lines match), skipping the parse + `FieldMap`
allocation for the other 99% cuts wall-clock by ~85% on both logfmt and JSON, and
the parallel path (F) sees the same ~60% win. The benefit scales smoothly with
selectivity (B, 20% match → ~56%). At 100% match (C) the pre-filter can skip
nothing and becomes pure overhead — a single `memchr`-anchored substring scan per
line — which the clean measurement shows is at the noise floor (±0.2%), because
the token is found near the start of each line and the scan cost is a rounding
error next to parsing. When the safety gate closes (D no filter, E context) the
pre-filter is inert and timings match the baseline within noise. Correctness is
byte-identical across the differential matrix, so the large wins come with no
observable behavior change in the covered configurations.

One documented, gate-bounded behavior difference exists outside that matrix: a
malformed line that the pre-filter drops (because it lacks the level token) is
never parsed, so a parse error it would have raised is not reported — identical
to how the existing pre-parse line filters (`--keep-lines`/`--ignore-lines`)
already behave, and rendered unobservable under `--stats`/`--discover` (which
disable the pre-filter) and on well-formed input.
